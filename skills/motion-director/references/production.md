# Установка и производство

Читай при отсутствии инструментов, первом запуске проекта или затруднениях с рендером.
Актуальный технический контракт задают установленные скиллы HyperFrames и справка CLI.
Официальные источники: [репозиторий](https://github.com/heygen-com/hyperframes), [документация](https://hyperframes.heygen.com/docs).

## Подготовка

1. Найди готовый проект и доступные инструменты. Не переустанавливай исправную среду ради каждого ролика.
2. Для локального рендера нужны Node.js 22+ с npm, FFmpeg/ffprobe и поддерживаемый Chromium/Chrome. Для отдельных генераторов могут понадобиться Python и дополнительные библиотеки — только по выбранной задаче.
3. Если нужных инструментов нет, установи их доступным в среде способом в рамках запроса на создание видео. Используй существующий управляемый runtime, если он предоставлен. Если установка недоступна, сообщи конкретное ограничение и продолжи сценарную работу.
4. Установи недостающие скиллы HyperFrames:

```sh
npx --yes hyperframes@latest skills update
```

Прочитай установленный hyperframes и выбранный им workflow. Workflow устанавливается отдельно; например, для общего объясняющего ролика:

```sh
npx --yes hyperframes@latest skills update general-video
```

Проверяй результат установки. Не подменяй отсутствующие инструкции догадками и не скачивай все workflow без необходимости.

## Новый проект

Следуй выбранному workflow. Минимальный пример для нового общего ролика:

```sh
npx --yes hyperframes@latest init video-demo --non-interactive --example=blank --skill=general-video
cd video-demo
```

Имя папки замени на осмысленное имя ролика. Init выполняется до записи BRIEF.md в новую папку; существующий проект повторно не инициализируется.

В папке проекта используй созданный package.json. При отсутствии package.json сначала выполни npm init -y. Если нужные зависимости ещё не заданы, типовой локальный набор:

```sh
npm install --save-exact hyperframes gsap ffmpeg-static ffprobe-static
```

GSAP нужен при выборе этой библиотеки анимации. Статические пакеты FFmpeg нужны, если подходящего системного FFmpeg/ffprobe нет. Исполняемые файлы из пакетов подключи к окружению процесса рендера; одной установки недостаточно, если CLI их не находит. Используй пути, возвращаемые пакетами, вместо жёстких путей с конкретного компьютера.

Сохрани package.json и lock-файл. Для существующего проекта используй его команды и зафиксированные версии; обновления выполняй по процедуре hyperframes с последующей проверкой.

## Сборка и проверка

Композиция создаётся по hyperframes-core, движения — по профильным скиллам. Не начинай с полного много­минутного рендера: сначала проверь кадры и наиболее сложные переходы.

Типовые команды из папки проекта; готовые скрипты package.json имеют приоритет:

```sh
npx hyperframes check --contrast
npx hyperframes snapshot --at 0,3,8
npx hyperframes render --fps 30 --quality high --output out.mp4
ffprobe -v error -show_format -show_streams out.mp4
ffmpeg -hide_banner -nostats -xerror -i out.mp4 -f null -
```

Времена snapshot выбери по фактическим сценам: установившийся кадр, вход/выход и стык. Предпросмотр и согласование выполняй в ранее выбранном совместном или автономном режиме.

На Windows сохраняй служебные процессы скрытыми или headless. Для материалов сетевого диска удобно рендерить локально, затем копировать результат в проект и сверять контрольную сумму. Управление мышью и клавиатурой требуется только для недостающих реальных снимков; после захвата освободи рабочий стол.

При приближении анимируй внутренний слой изображения. Положение рамок связывай с геометрией исходника; толщину и отступы проверяй в готовом кадре. Ритм звука привязывай к сценарию, проверяй начало, конец и отсутствие перегруза.

Выдача: MP4, исходная композиция, сценарий, использованные ассеты и команды повторной сборки. node_modules, временные кадры и полный набор чужих референсов в выдачу не копируются.
