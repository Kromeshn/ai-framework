# Выполнить применимые проверки пакета и устранить замечания

Построить локальную описательную BPMN-схему. Сведения синтетические. Все обычные действия — task; полные названия действий и документов сохранить. Схема должна различать условно запускаемые параллельные ветки и синхронизацию только запущенных проверок.

Один экземпляр — один учебный пакет. Старт: «Получен учебный пакет с непустым перечнем проверок». Входные логические признаки economicsRequired, technologyRequired, operationsRequired, qualityRequired независимы. Хотя бы один равен true; разрешены все 15 непустых комбинаций, включая четыре true одновременно. Пакеты с пустым перечнем не запускают этот процесс. Признаки фиксируются в начале и сохраняются на всех повторах. Ветки не являются взаимоисключающими.

Один пул; первая дорожка «Документы» используется только для визуального размещения dataObjectReference над связанными действиями. У неё нет flowNodeRef на документы. Далее дорожки «Координатор», «Эксперт по расчётам», «Технический эксперт», «Эксперт по исполнению», «Эксперт по качеству».

1. Координатор выполняет «Подготовить комплект материалов и зафиксировать применимые направления независимой проверки». Создаётся «Комплект материалов для независимых проверок учебного решения».
2. Первый проход и возврат с доработки объединяются исключающим сходящимся шлюзом «Комплект готов к очередной проверке?». Затем включающий расходящийся шлюз «Какие направления проверки применимы?» запускает каждую ветку с true независимо от остальных. Потока по умолчанию нет, потому что пустой набор исключён условием входа.
3. Ветка economicsRequired=true, подпись «Требуются расчёты»: эксперт по расчётам выполняет «Проверить исходные расчёты и обоснованность ожидаемых затрат и результатов». Читается комплект, создаётся «Заключение о расчётах, затратах и ожидаемом результате».
4. Ветка technologyRequired=true, подпись «Требуется техническая проверка»: технический эксперт выполняет «Проверить техническую осуществимость предложенного решения и ограничения его применения». Читается комплект, создаётся «Заключение о технической осуществимости и ограничениях применения».
5. Ветка operationsRequired=true, подпись «Требуется проверка исполнения»: эксперт по исполнению выполняет «Проверить последовательность выполнения работ и достаточность предусмотренных ресурсов». Читается комплект, создаётся «Заключение о порядке выполнения и достаточности ресурсов».
6. Ветка qualityRequired=true, подпись «Требуется проверка качества»: эксперт по качеству выполняет «Проверить критерии качества результата и способы подтверждения их выполнения». Читается комплект, создаётся «Заключение о критериях качества и способах их подтверждения».
7. Все четыре выхода ведут во включающий сходящийся шлюз «Все запущенные проверки завершены?». Он ожидает только ветки, действительно запущенные в текущем проходе. После него координатор выполняет «Провести совместный контроль заключений по всем запущенным направлениям и свести замечания» с участием экспертов запущенных направлений. Читаются только созданные заключения. У незапущенных направлений документ не требуется; их входы в ioSpecification следует обозначить optionalInputRefs. Создаётся «Сводное заключение совместного контроля с перечнем замечаний» и устанавливается определённое логическое поле hasIssues.
8. Исключающий шлюз «Есть замечания к комплекту материалов?» имеет две ветки. «Да» (hasIssues=true): координатор выполняет «Доработать комплект материалов по сводным замечаниям и направить на повторную проверку». Читаются комплект и сводное заключение, обновляется тот же комплект; управление возвращается перед включающим разделением. Повторяются все первоначально выбранные проверки. «Нет» (hasIssues=false): координатор выполняет «Зафиксировать положительный результат совместного контроля комплекта материалов», затем конец «Комплект проверен, замечания отсутствуют».

Число циклов доработки не ограничивается; завершение возможно после прохода без замечаний. Между соседними циклами не остаются активные проверки предыдущего прохода. Создание документов показать dataOutputAssociation, чтение — dataInputAssociation с корректными ioSpecification. Нельзя заменить inclusive-разделение на XOR или обязательный parallel fork.
