# Подготовить заключение с напоминанием о сроке

Построить локальную описательную BPMN-схему с развёрнутым встроенным подпроцессом. Все названия и сведения синтетические. Действия по умолчанию показать обычными task; внешнее сообщение показать отдельным messageFlow между пулами. Полные русские подписи сохранить.

Один экземпляр — один комплект материалов. Основной пул «Рассмотрение учебного комплекта». Второй пул «Внешний получатель заключения» — black box без processRef и внутренних действий. Родительский процесс не содержит дорожек. Подпроцесс содержит три дорожки ответственности «Координатор», «Эксперт», «Контролёр» и отдельную верхнюю дорожку «Документы» только для визуальной группировки объектов данных; документы не включаются в flowNodeRef.

Родительский порядок: простой старт «Получен комплект материалов для учебного заключения» → развёрнутый встроенный подпроцесс «Подготовить проверенное заключение по комплекту материалов» → обычная задача «Передать итоговое заключение внешнему получателю после завершения внутреннего рассмотрения» → простой конец «Итоговое заключение передано внешнему получателю». Из задачи передачи в black-box pool направляется единственный messageFlow «Итоговое заключение по комплекту материалов» с одноимённым messageRef. Подтверждения получения и обратного сообщения в границах кейса нет; завершение означает передачу, а не подтверждённое получение.

Внутри подпроцесса:

1. Простой старт «Начато рассмотрение комплекта» на дорожке координатора возникает при запуске подпроцесса родителем. Координатор выполняет «Подготовить комплект материалов к рассмотрению и проверить наличие необходимых пояснений», создавая «Комплект материалов и пояснений для подготовки учебного заключения».
2. Эксперт выполняет «Изучить материалы и подготовить рабочее заключение с обоснованием выводов и ограничений». Действие читает комплект и создаёт «Рабочее заключение эксперта с обоснованием выводов и ограничений».
3. На задаче эксперта закреплён непрерывающий boundary timer «Прошло 2 суток с начала изучения», cancelActivity=false, timeDuration=P2D. Таймер однократный: если задача завершается раньше двух суток, таймер не срабатывает. Если через двое суток задача ещё активна, создаётся дополнительная ветка, а исходная задача продолжает выполнение. Повторяющегося timeCycle нет.
4. Ветка таймера ведёт на дорожку координатора к задаче «Уточнить у эксперта ожидаемый срок завершения и зарегистрировать ответ», затем к отдельному обычному концу «Ожидаемый срок завершения зарегистрирован». Ветка не возвращает управление на задачу эксперта, не запускает её второй раз и не отменяет рассмотрение.
5. После нормального завершения экспертной задачи контролёр выполняет «Проверить аргументацию рабочего заключения и оформить итоговое заключение по материалам», читая комплект и рабочее заключение; создаётся «Итоговое заключение после проверки аргументации». Затем обычный конец «Итоговое заключение подготовлено». В рамках кейса контролёр сам завершает проверку и оформление; отдельной ветки исправления не предусмотрено.
6. Подпроцесс завершён, когда основной путь достиг конца и отсутствуют другие активные ветки. Если таймер сработал и уточнение срока ещё выполняется, родитель ждёт его завершения даже при готовом итоговом заключении. Если уточнение завершено раньше, ожидание продолжается только по основному пути. Terminate end, искусственный parallel join и повторная активация основной задачи не требуются.

Все три документа разместить в верхней полосе подпроцесса. Создание показать dataOutputAssociation, чтение — dataInputAssociation через корректные ioSpecification. Последовательность внутри подпроцесса не пересекает его границу; с родителем соединяется сам subprocess. Исходный минимальный BPMNShape с isExpanded=true обозначает только требование раскрытия и не задаёт желательную геометрию.
