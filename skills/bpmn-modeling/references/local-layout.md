# Локальная раскладка без Storm

Этот путь применяется для нового BPMN XML и разрешённой пользователем полной перекомпоновки. Подключение Storm, импорт в сторонний сервис и сетевой доступ во время построения не нужны. Для точечной правки сохраняется текущая DI; полная раскладка не запускается.

## Рабочий цикл

1. Сначала составить корректную семантическую модель: процессы, участники, дорожки, задачи, шлюзы и связи. Для новой модели координаты вручную не рассчитывать. Порядок дорожек в XML задаёт желаемый порядок сверху вниз. Пустая дорожка «Документы» допустима как визуальная полоса; объекты данных не входят в `flowNodeRef`.
2. Запустить единую команду из установленного навыка:

   `python <skill>/scripts/bpmn_layout.py <model.bpmn> --report-dir <temporary-preview-dir>`

   Каталог отчёта должен быть отдельным: исходник и итоговый BPMN не должны находиться внутри него. В существующей модели с DI полная перекомпоновка требует `--reflow`; этот флаг применим только в рамках поручения на перераскладку. По умолчанию успешно проверенный результат записывается в тот же файл. `--output` позволяет создать новый ещё не существующий файл.
3. Прочитать `layout-report.json`. Успех требует `status: pass`, `output_written: true`, отсутствия предупреждений импорта и неизменной семантики. Конвейер создаёт изображения **каждой** BPMNDiagram, включая отдельные уровни свёрнутых подпроцессов. В `preview/report.json` перечислены файлы обзорных PNG и фрагментов 1:1.
4. Открыть полученные PNG через доступное средство просмотра изображений. Для крупной схемы осмотреть обзор и фрагменты 1:1 с ветвлениями, возвратами, таймерами и документами. Проверить читаемость, разумную длину маршрутов, отсутствие пустых полос и слипшихся веток. Отчёт проверяет геометрию, но не оценивает весь визуальный баланс и смысл.
5. Если автоматическая проверка остановила запись, исходный файл сохранён. Исправить только DI в `candidate.bpmn` из каталога отчёта, повторить render и audit, осмотреть изображения. Перед переносом исправленной DI в исходник снова проверить его SHA-256 и семантический отпечаток. Не объявлять неудавшуюся автоматическую попытку готовым результатом и не менять процесс ради устранения пересечений.

Итог отдаётся после этого цикла, без промежуточного предъявления неосмотренной схемы. «С первого раза» означает первую выдачу пользователю после проверки, а число автоматических и ручных исправлений учитывается отдельно.

## Зависимости и команды проверки

Требуются Python 3.10+ с `lxml`, Node.js 18+ и Playwright с установленным Chromium либо локальным Edge/Chrome. Если доступны bundled workspace dependencies, пути получить их штатным инструментом. Node определяется через PATH или локальный Codex runtime; альтернативный путь задаётся `--node`. Renderer принимает `--playwright <module-path>` и `--browser <browser-executable>`; конвейер передаёт эти параметры дальше. Отсутствующие зависимости обозначаются явно, поддельный PNG вместо настоящего импорта не создаётся.

Повторная проверка после точечной правки:

```
node <skill>/scripts/bpmn_render.cjs <model.bpmn> --out-dir <preview-dir>
python <skill>/scripts/geometry_audit.py <model.bpmn> --render-report <preview-dir>/report.json --output <audit.json>
```

`status: incomplete` означает отсутствие измеренных подписей, а не успешную проверку. Старый render отвергается по SHA-256. Снимки создаются кодом в отдельном headless процессе; управление пользовательским браузером или Computer Use не требуется. Встроенный watermark bpmn.io сохраняется согласно лицензии.

## Что делает компоновка

В навык включён закреплённый `bpmn-auto-layout 2.0.0-alpha.2`: размещение по связям процесса, дорожки, пулы и подпроцессы. Размер задач увеличен до 220 × 104 для русских названий; внешние подписи — до 150. Затем локальные модули располагают документы сверху. Предварительный рендер измеряет настоящие подписи, после чего конфликтующие ортогональные линии разводятся по отдельным маршрутам. Основные потоки имеют приоритет; поиск ограничен бюджетом, который отражается в отчёте. Порядок исполнения, роли, условия, таймеры и расширения исходного XML сохраняются: из результата движка переносится только BPMN DI.

Это предварительная версия внешней библиотеки, закреплённая внутри навыка. Обновление автоматически не выполняется. В сложном неплоском графе, очень длинных подписях или необычной вложенности возможна ручная коррекция DI. Отказ проверки должен оставаться видимым. Полная гарантия отсутствия пересечений для любого процесса не заявляется.

Исходные версии, воспроизводимая сборка и лицензии находятся в `scripts/vendor-src`, `scripts/build_vendor.cjs` и `scripts/vendor`. Встроенные библиотеки работают локально; npm требуется только при осознанной пересборке навыка. Не изменять vendor bundle вручную — корректировать воспроизводимый patch в build script и повторять регрессию.
## Когда все пересечения убрать невозможно

При плотных связях документов граф может оказаться непланарным: на одной плоскости нельзя сохранить все связи без пересечения. Конвейер включает необязательный `topology_report.py`, использующий уже установленный NetworkX; отсутствие пакета даёт `unavailable`, без сетевой установки. Результат `planar` не гарантирует удачную раскладку с заданными дорожками. Результат `nonplanar` относится к объединённому графу на одной плоскости; отдельные planes подпроцессов нужно оценивать раздельно.

При неудаче сначала прочитать эту диагностику и аудит. Не повторять полную раскладку бесконечно: после двух безуспешных ручных проходов обозначить конкретные оставшиеся пересечения и причину. Сохранение общего смысла и всех связей имеет приоритет перед нулевым счётчиком. Не удалять ассоциации и не дробить процесс без основания. Если ноль пересечений невозможен, предложить осмысленное разделение уровней или оставить явно объяснённые пересечения пунктирных связей. Перекрытия текста, стрелки сквозь задачи и общие отрезки разных стрелок этим не оправдываются. Не объявлять такой результат автоматическим `pass`.

## Уточнения по результатам свежих контекстов

- Увеличение `BPMNLabel/Bounds.width` само по себе не расширяет внешний текст в проверенной версии bpmn-js: он может продолжать переноситься в колонке около 90 единиц. Не увеличивать поле подписи в расчёте на иной перенос строк. При ручной правке сохранять измеренный зазор 8–12 единиц между нижней строкой и значком документа; после правки повторять измерение.
- После изменения маршрута подпись условия может остаться у старого отрезка. Проверять, что «Да», «Нет» и другие условия стоят у фактического выхода соответствующего шлюза. Отсутствие наложений само по себе этого не доказывает.
- Автоматический `pass` разрешает сохранение, но не означает оптимальную компактность. При осмотре убрать очевидные пустые полосы и лишние обходы, не затрагивая смысл и сохраняя успешный повторный аудит.
