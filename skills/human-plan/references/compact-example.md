# Пример плотности и уровня

Пример показывает, как сохранить намерение, решения и причины в малом цикле. Имена, значения и отказ от переноса истории относятся только к этому brief; содержание другого плана определяется его источниками.

# Источник документа в журнале

Журнал должен различать ручные загрузки и вызовы 1С для фильтрации в BI. Пустой `doc_guid` этого не позволяет.

| Изменение | Причина |
|---|---|
| Каждая запись получает обязательный `source`: `/extract` → `extract`, `/v1/responses` → `responses` | Источник известен по входу; отличается от `route` (`text`/`vision`), не привязан к URL |
| `doc_guid` удаляется из журнала, чтения `/extract-log` и приёма `/extract`, включая приём со стороны 1С | Поле было опциональным, на ответ не влияло; дополнительное согласование не требуется |
| Журнал пересоздаётся без переноса старых строк | Прод-журнала нет |

```mermaid
flowchart LR
    E[/extract] -->|extract| J[(Журнал)]
    R[/v1/responses] -->|responses| J
    J --> L[/extract-log]
```

Ответы распознавания сохраняются; `source` остаётся только в журнале. BI и документация по `doc_guid` — отдельный проход.

**Приёмка:** на работающем сервисе с новой схемой отправить реальный счёт через оба API, прочитать `/extract-log`. Источники соответствуют входам, не пусты; `doc_guid` отсутствует. Ответы прежние, без `source`.
